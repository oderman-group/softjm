Documentación técnica – Integración Orion ↔ Ofima

Clientes, productos, inventario, pedidos y bodegas. Para el equipo de desarrollo Ofima.

1. Resumen de flujos

La integración es bidireccional:

  • Orion → Ofima: Orion (CRM) envía a Ofima (ERP) cuando se crean o actualizan clientes, productos o pedidos. Ofima debe exponer una URL por módulo que acepte POST (crear) y PUT (actualizar), con HTTP Basic Auth.
  • Ofima → Orion: Ofima envía a Orion cuando desea sincronizar clientes, productos, inventario (existencias por bodega) o bodegas. Orion expone endpoints REST; autenticación: Bearer JWT (recomendado) o HTTP Basic Auth. El JWT se obtiene del endpoint de login.

URLs de Orion (para endpoints que Ofima llama):

EntornoURL base
Pruebashttps://developer.orioncrm.com.co/softjm/
Producciónhttps://app.orioncrm.com.co/softjm/

Los endpoints de Orion (login, clientes, productos, inventario, bodegas) se construyen añadiendo la ruta al final de la URL base (ej. https://developer.orioncrm.com.co/softjm/usuarios/api/orion/auth.php).

Credenciales de autenticación: Las credenciales (usuario, contraseña o acceso al login JWT) para ambos flujos deben solicitarse al administrador técnico del sistema. No se incluyen en esta documentación por seguridad.

2. Autenticación común (Orion → Ofima)

Cuando Orion llama a Ofima, Orion envía:

  • Headers: Content-Type: application/json, Accept: application/json
  • Autenticación: HTTP Basic Auth (usuario y contraseña configurados en Orion por módulo). Ofima debe validar estas credenciales y responder 401 si son inválidas. Las credenciales que Orion utiliza para llamar a Ofima las asigna el administrador técnico del sistema; Ofima debe solicitarlas para configurar la validación en su lado.

En todos los casos, respuesta HTTP 2xx = éxito; 4xx/5xx = error (Orion lo registra y no reintenta en la misma acción).

Para probar estos contratos en Postman, usa el botón Descargar colección Postman de la parte superior. La carpeta «Ofima hacia Orion» llama a los endpoints de Orion; la carpeta «Orion hacia Ofima» trae los cuerpos que Ofima debe recibir, con Basic Auth.

3. Endpoints que Ofima debe exponer (Orion → Ofima)

Orion tiene configurada una URL por módulo en api_configuracion (módulo: clientes, productos o pedidos; dirección: orion_ofima). Ofima debe implementar una URL que acepte POST y PUT con el cuerpo JSON indicado en cada apartado.

3.1 Clientes

MétodosPOST crear · PUT actualizar
URLLa que Ofima asigne y se configure en Orion (ej. https://api.ofima.com/integracion/orion/clientes).
AuthHTTP Basic Auth

Payload (cuerpo JSON) – Orion envía (mapeo por defecto):

{
  "identificacion": "900123456-1",
  "nombre": "Cliente Ejemplo S.A.S",
  "email": "contacto@ejemplo.com",
  "telefono": "6011234567",
  "direccion": "Calle 123",
  "ciudad": "05001",
  "celular": "3001234567",
  "referencia": "",
  "id_empresa": 1
}

identificacion = NIT/documento del cliente en Orion (clave para identificar). ciudad = código DIAN (ciu_cod_dian, ej. 05001 Medellín, 11001 Bogotá) — no el nombre de la ciudad. Orion convierte su ciu_id interno a ese código antes de enviar. id_empresa = ID de empresa en Orion. El mapeo puede personalizarse en Orion con api_mapeo_campos (módulo clientes).

4. Endpoints que Orion expone (Ofima → Orion)

URL base según entorno:

  • Pruebas: https://developer.orioncrm.com.co/softjm/
  • Producción: https://app.orioncrm.com.co/softjm/

Ejemplo de URL completa para login en pruebas: https://developer.orioncrm.com.co/softjm/usuarios/api/orion/auth.php. En producción usar https://app.orioncrm.com.co/softjm/usuarios/api/orion/ + el archivo correspondiente (auth.php, clientes-recibir.php, etc.).

Autenticación: En todos los endpoints, Ofima puede usar:

  • Bearer JWT (recomendado): header Authorization: Bearer <token>. El token se obtiene del endpoint de login (apartado 4.1).
  • HTTP Basic Auth: usuario y contraseña configurados en Orion para la dirección ofima_orion (por módulo). Si no se envía JWT, Orion espera Basic Auth.

Las credenciales (usuario y contraseña para login/Basic Auth) deben solicitarse al administrador técnico del sistema; no se proporcionan en esta documentación.

Si se usa JWT, el id_empresa se toma del token; si se usa Basic Auth, puede enviarse id_empresa en el body (opcional, por defecto 1).

4.1 Login (obtener JWT)

MétodoPOST
URL/softjm/usuarios/api/orion/auth.php
AuthBasic Auth o body JSON con usuario y password

Body opcional: { "usuario": "...", "password": "...", "id_empresa": 1 }

Respuesta 200 (éxito):

{
  "success": true,
  "message": "Token generado correctamente",
  "token": "eyJ0eXAiOiJKV1QiLCJhbGc...",
  "expires_in": 43200,
  "token_type": "Bearer"
}

Usar token en Authorization: Bearer <token> en el resto de peticiones. expires_in en segundos (p. ej. 12 h).

MétodoPOST

Body JSON (campos requeridos: identificacion, nombre):

{
  "identificacion": "900123456-1",
  "nombre": "Cliente Ejemplo S.A.S",
  "email": "contacto@ejemplo.com",
  "telefono": "6011234567",
  "direccion": "Calle 123",
  "ciudad": "05001",
  "celular": "3001234567",
  "referencia": "",
  "id_empresa": 1
}
CampoDescripción
identificacionNIT/documento (clave para crear o actualizar).
ciudadCódigo DIAN (ciu_cod_dian), ej. 05001, 11001. No enviar el nombre (incorrecto: "Bogotá"; correcto: "11001"). Orion lo homologa a ciu_id y asigna cli_zona = ciu_departamento.

Orion identifica al cliente por identificacion. Si existe, actualiza; si no, crea. Respuesta 200: { "success": true, "message": "Cliente sincronizado correctamente", "cliente_id": 5, "identificacion": "900123456-1", "operacion": "CREATE" | "UPDATE" }.

CampoColumna OrionQué enviar

Al recibir, Orion homologa códigos Ofima (linea/sublinea/grupo/clasificacion_1 o equivalentes en grupo_id/categoria_id/marca_id) a IDs internos (catp_id/mar_id) y los guarda en prod_grupo1, prod_categoria, prod_marca, prod_grupo3. Nunca persiste el código Ofima en esas columnas. Al enviar a Ofima (sección 3.2) hace el camino inverso (ID → código). utilidad: 0–100 o 0–1. Orion identifica por referencia. Respuesta 200: { "success": true, "message": "Producto sincronizado correctamente", "producto_id": 10, "referencia": "COD001", "operacion": "CREATE" | "UPDATE" }.

4.4 Inventario (Ofima → Orion)

MétodoPOST
URL/softjm/usuarios/api/orion/inventario-recibir.php
AuthBearer JWT o Basic Auth

Actualiza existencias por producto y bodega. Orion actualiza productos_bodegas y recalcula prod_existencias del producto.

Un solo ítem:

{
  "referencia": "COD001",
  "bodega_referencia": "BOGOTA",
  "existencias": 50
}

O por producto_id de Orion: { "producto_id": 123, "bodega_referencia": "BOGOTA", "existencias": 50 }.

Lote (varios ítems):

{
  "items": [
    { "referencia": "COD001", "bodega_referencia": "BOGOTA", "existencias": 50 },
    { "referencia": "COD002", "bodega_referencia": "BOGOTA", "existencias": 30 }
  ]
}

Requerido por ítem: referencia o producto_id, bodega_referencia (columna bod_referencia), existencias (número ≥ 0). Orion busca la bodega por ese código y la empresa. Respuesta 200: { "success": true, "message": "Inventario sincronizado correctamente", "procesados": 2, "resultados": [ { "producto_id": 10, "bodega_referencia": "BOGOTA", "bodega_id": 1, "existencias": 50, "operacion": "UPDATE" }, ... ] }.

4.5 Bodegas (Ofima → Orion)

MétodoPOST
URL/softjm/usuarios/api/orion/bodegas-recibir.php
AuthBearer JWT o Basic Auth

Body JSON (referencia y nombre obligatorios):

{
  "referencia": "BOGOTA",
  "nombre": "BODEGA BOGOTÁ",
  "ciudad": "11001",
  "id_empresa": 1
}

referencia = código de la bodega en Ofima (Orion la usa para identificar y sincronizar). ciudad = código DIAN (ciu_cod_dian); Orion busca ese código en localidad_ciudades y guarda bod_ciudad con el ciu_id encontrado. La bodega recibida queda habilitada. Si la bodega ya existe por referencia, se actualiza; si no, se crea. Respuesta 200: { "success": true, "message": "Bodega sincronizada correctamente", "bodega_id": 1, "operacion": "CREATE" | "UPDATE" }.

5. Resumen para implementación en Ofima

  1. Exponer 3 URLs que Orion llamará (clientes, productos, pedidos), aceptando POST y PUT, con HTTP Basic Auth y cuerpo JSON. Responder 2xx en éxito.
  2. Para enviar datos a Orion: obtener JWT con POST a auth.php (Basic o JSON usuario/password); luego usar Authorization: Bearer <token> en clientes, productos, inventario y bodegas.
  3. Clientes: Ofima envía a Orion identificacion + nombre (y demás campos). ciudad debe ser el código DIAN (ej. 05001), no el nombre de la ciudad. Orion crea/actualiza por NIT y homologa la ciudad a ciu_id.
  4. Productos (Ofima → Orion): Ofima envía códigos (linea/sublinea/grupo o grupo_id/categoria_id/marca_id); Orion los resuelve a IDs internos. Default categoría = 1 si no hay sublínea válida.
  5. Productos (Orion → Ofima): Orion homologa y envía códigos Ofima en linea/sublinea/grupo/clasificacion_1/habilitado junto a los campos que Ofima ya usa.
  6. Inventario: Ofima envía referencia (o producto_id), bodega_referencia (bod_referencia) y existencias; un objeto o array en items para lote.
  7. Bodegas: Ofima envía referencia y nombre (y opcionalmente ciudad) para crear/actualizar bodegas en Orion. Las bodegas deben existir en Orion, con bod_referencia, antes de enviar inventario.
