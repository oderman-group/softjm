Documentación técnica – Integración Orion ↔ Ofima

Clientes, productos, inventario, pedidos y bodegas. Para el equipo de desarrollo Ofima.

1. Resumen de flujos

La integración es bidireccional:

  • Orion → Ofima: Orion (CRM) envía a Ofima (ERP) cuando se crean o actualizan clientes, productos o pedidos. Ofima debe exponer una URL por módulo que acepte POST (crear) y PUT (actualizar), con HTTP Basic Auth.
  • Ofima → Orion: Ofima envía a Orion cuando desea sincronizar clientes, productos, inventario (existencias por bodega) o bodegas. Orion expone endpoints REST; autenticación: Bearer JWT (recomendado) o HTTP Basic Auth. El JWT se obtiene del endpoint de login.

URLs de Orion (para endpoints que Ofima llama):

EntornoURL base
Pruebashttps://developer.orioncrm.com.co/
Producciónhttps://app.orioncrm.com.co/

Los endpoints de Orion (login, clientes, productos, inventario, bodegas) se construyen añadiendo la ruta al final de la URL base (ej. https://developer.orioncrm.com.co/usuarios/api/orion/auth.php).

2. Autenticación común (Orion → Ofima)

Cuando Orion llama a Ofima, Orion envía:

  • Headers: Content-Type: application/json, Accept: application/json
  • Autenticación: HTTP Basic Auth (usuario y contraseña configurados en Orion por módulo). Ofima debe validar estas credenciales y responder 401 si son inválidas.

En todos los casos, respuesta HTTP 2xx = éxito; 4xx/5xx = error (Orion lo registra y no reintenta en la misma acción).

3. Endpoints que Ofima debe exponer (Orion → Ofima)

Orion tiene configurada una URL por módulo en api_configuracion (módulo: clientes, productos o pedidos; dirección: orion_ofima). Ofima debe implementar una URL que acepte POST y PUT con el cuerpo JSON indicado en cada apartado.

3.1 Clientes

MétodosPOST crear · PUT actualizar
URLLa que Ofima asigne y se configure en Orion (ej. https://api.ofima.com/integracion/orion/clientes).
AuthHTTP Basic Auth

Payload (cuerpo JSON) – Orion envía (mapeo por defecto):

{
  "identificacion": "900123456-1",
  "nombre": "Cliente Ejemplo S.A.S",
  "email": "contacto@ejemplo.com",
  "telefono": "6011234567",
  "direccion": "Calle 123",
  "ciudad": "Bogotá",
  "celular": "3001234567",
  "referencia": "",
  "id_empresa": 1
}

identificacion = NIT/documento del cliente en Orion (clave para identificar). id_empresa = ID de empresa en Orion. El mapeo puede personalizarse en Orion con api_mapeo_campos (módulo clientes).

3.2 Productos

MétodosPOST crear · PUT actualizar
URLLa que Ofima asigne (ej. https://api.ofima.com/integracion/orion/productos).
AuthHTTP Basic Auth

Orion envía los campos según la tabla api_mapeo_campos (módulo productos). Si no hay mapeo configurado, no se envía payload por defecto; conviene acordar con Orion los nombres de campo. Típicamente: referencia, nombre, costo, utilidad (0–100), precio, categoria_id, grupo_id, marca_id, proveedor_id, descripcion_corta, descripcion_larga, id_empresa. Validaciones en Orion: costo ≥ 0, utilidad entre 0 y 100, precio ≥ 0 si se envía.

3.3 Pedidos

MétodosPOST crear · PUT actualizar
URLLa que Ofima asigne (ej. https://api.ofima.com/integracion/orion/pedidos).
AuthHTTP Basic Auth

Payload (cuerpo JSON):

{
  "numero": "123",
  "cliente_identificacion": "900123456-1",
  "cliente_id": 5,
  "fecha": "2025-02-26",
  "observaciones": "Texto opcional",
  "items": [
    {
      "referencia": "COD001",
      "producto_id": 10,
      "cantidad": 2,
      "valor": 15000.00,
      "descuento": 0,
      "impuesto": 19
    }
  ],
  "id_empresa": 1
}
CampoDescripción
numeroID del pedido en Orion (pedid_id).
cliente_identificacionNIT/documento del cliente.
fechaYYYY-MM-DD.
items[]Solo líneas de producto. Los combos se envían desglosados en productos (cada producto del combo con su referencia, cantidad, valor unitario, descuento, impuesto).

Nota: Si el pedido ya está facturado en Orion, Orion no envía UPDATE a Ofima (respuesta de error interna).

4. Endpoints que Orion expone (Ofima → Orion)

URL base según entorno:

  • Pruebas: https://developer.orioncrm.com.co
  • Producción: https://app.orioncrm.com.co

Ejemplo de URL completa para login en pruebas: https://developer.orioncrm.com.co/usuarios/api/orion/auth.php. En producción usar https://app.orioncrm.com.co/usuarios/api/orion/ + el archivo correspondiente (auth.php, clientes-recibir.php, etc.).

Autenticación: En todos los endpoints, Ofima puede usar:

  • Bearer JWT (recomendado): header Authorization: Bearer <token>. El token se obtiene del endpoint de login (apartado 4.1).
  • HTTP Basic Auth: usuario y contraseña configurados en Orion para la dirección ofima_orion (por módulo). Si no se envía JWT, Orion espera Basic Auth.

Si se usa JWT, el id_empresa se toma del token; si se usa Basic Auth, puede enviarse id_empresa en el body (opcional, por defecto 1).

4.1 Login (obtener JWT)

MétodoPOST
URL/usuarios/api/orion/auth.php
AuthBasic Auth o body JSON con usuario y password

Body opcional: { "usuario": "...", "password": "...", "id_empresa": 1 }

Respuesta 200 (éxito):

{
  "success": true,
  "message": "Token generado correctamente",
  "token": "eyJ0eXAiOiJKV1QiLCJhbGc...",
  "expires_in": 43200,
  "token_type": "Bearer"
}

Usar token en Authorization: Bearer <token> en el resto de peticiones. expires_in en segundos (p. ej. 12 h).

4.2 Clientes (Ofima → Orion)

MétodoPOST
URL/usuarios/api/orion/clientes-recibir.php
AuthBearer JWT o Basic Auth

Body JSON (campos requeridos: identificacion, nombre):

{
  "identificacion": "900123456-1",
  "nombre": "Cliente Ejemplo S.A.S",
  "email": "contacto@ejemplo.com",
  "telefono": "6011234567",
  "direccion": "Calle 123",
  "ciudad": "Bogotá",
  "celular": "3001234567",
  "referencia": "",
  "id_empresa": 1
}

Orion identifica al cliente por identificacion (NIT/documento). Si existe, actualiza; si no, crea. Respuesta 200: { "success": true, "message": "Cliente sincronizado correctamente", "cliente_id": 5, "identificacion": "900123456-1", "operacion": "CREATE" | "UPDATE" }.

4.3 Productos (Ofima → Orion)

MétodoPOST
URL/usuarios/api/orion/productos-recibir.php
AuthBearer JWT o Basic Auth

Body JSON (campos requeridos: referencia, nombre):

{
  "referencia": "COD001",
  "nombre": "Producto ejemplo",
  "costo": 10000,
  "utilidad": 30,
  "precio": 13000,
  "categoria_id": 1,
  "grupo_id": null,
  "marca_id": null,
  "proveedor_id": null,
  "descripcion_corta": "",
  "descripcion_larga": "",
  "descuento1": null,
  "comision": null,
  "costo_dolar": null,
  "id_empresa": 1
}

utilidad: 0–100 (porcentaje) o 0–1 (factor decimal); Orion normaliza a 0–100. Si no se envía precio pero sí costo y utilidad, Orion calcula el precio. Validaciones: costo ≥ 0, utilidad 0–100, precio ≥ 0. Orion identifica por referencia; si existe actualiza, si no crea. Respuesta 200: { "success": true, "message": "Producto sincronizado correctamente", "producto_id": 10, "referencia": "COD001", "operacion": "CREATE" | "UPDATE" }.

4.4 Inventario (Ofima → Orion)

MétodoPOST
URL/usuarios/api/orion/inventario-recibir.php
AuthBearer JWT o Basic Auth

Actualiza existencias por producto y bodega. Orion actualiza productos_bodegas y recalcula prod_existencias del producto.

Un solo ítem:

{
  "referencia": "COD001",
  "bodega_id": 1,
  "existencias": 50
}

O por producto_id de Orion: { "producto_id": 123, "bodega_id": 1, "existencias": 50 }.

Lote (varios ítems):

{
  "items": [
    { "referencia": "COD001", "bodega_id": 1, "existencias": 50 },
    { "referencia": "COD002", "bodega_id": 1, "existencias": 30 }
  ]
}

Requerido por ítem: referencia o producto_id, bodega_id, existencias (número ≥ 0). La bodega debe existir en Orion y pertenecer a la empresa. Respuesta 200: { "success": true, "message": "Inventario sincronizado correctamente", "procesados": 2, "resultados": [ { "producto_id": 10, "bodega_id": 1, "existencias": 50, "operacion": "UPDATE" }, ... ] }.

4.5 Bodegas (Ofima → Orion)

MétodoPOST
URL/usuarios/api/orion/bodegas-recibir.php
AuthBearer JWT o Basic Auth

Body JSON (referencia y nombre obligatorios):

{
  "referencia": "BOD-01",
  "nombre": "Bodega Principal",
  "ciudad": 1,
  "id_empresa": 1
}

referencia = código de la bodega en Ofima (Orion la usa para identificar y sincronizar). Si la bodega ya existe por referencia, se actualiza; si no, se crea. Respuesta 200: { "success": true, "message": "Bodega sincronizada correctamente", "bodega_id": 1, "operacion": "CREATE" | "UPDATE" }.

5. Resumen para implementación en Ofima

  1. Exponer 3 URLs que Orion llamará (clientes, productos, pedidos), aceptando POST y PUT, con HTTP Basic Auth y cuerpo JSON. Responder 2xx en éxito.
  2. Para enviar datos a Orion: obtener JWT con POST a auth.php (Basic o JSON usuario/password); luego usar Authorization: Bearer <token> en clientes, productos, inventario y bodegas.
  3. Clientes: Ofima puede enviar a Orion con identificacion + nombre; Orion crea/actualiza por NIT.
  4. Productos: Ofima puede enviar referencia + nombre y opcionales (costo, utilidad, precio, etc.); Orion crea/actualiza por referencia.
  5. Inventario: Ofima envía referencia (o producto_id), bodega_id y existencias; un objeto o array en items para lote.
  6. Bodegas: Ofima envía referencia y nombre (y opcionalmente ciudad) para crear/actualizar bodegas en Orion. Las bodegas deben existir en Orion antes de enviar inventario por bodega_id.
